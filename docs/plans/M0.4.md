## Scope

In:

- **S1 Surah-mode rendering.** Amiri Quran shaping in Flutter; word hit-testing and
  highlight boxes; reflow at 200%; laying out and scrolling a long surah; cold start
  to a saved position. Also the last-line centring left partial by M0.2 and where the
  margin marks and page marks of `RD-02` and `RD-06` go.
- **S5 Downloads.** Resumable sequential queue, Wi-Fi only, verify then activate,
  update and rollback, on `LocalPackRepository.verify`.
- **S3, playback part.** 60 minutes with the screen locked; lock-screen, notification
  and headset controls (`AU-15`, `NF-09`). `AU-22` interruptions are watched in the
  same device session, not a gate.

Out: the S3 highlight part (needs B0.5); S2 (B0.3); S6 (packs); S4 and S7 (next
round, they need only S1); `OF-03` free-space display and `OF-07` (M1.4); every iOS
figure (D-042).

Sources: S1 uses registry row 1 (Tanzil, `Ready`), fetched only on the CI runner or
the device (D-072). S3 uses a tone generated at run time; no recitation has a rights
record yet (O-04). S5 uses synthetic packs. `lib/` is not changed; what the spikes
find is built in M1.2, M1.4 and M1.9.

## Where spike code lives (D-068)

`spike/` at the root of the app package, on the milestone branch. It imports
`package:holyquran/...` and `testing/`, so it uses the real data layer, widgets,
tokens and fonts, and `flutter analyze` and `dart format` cover it. The guards scan
`lib/` only, so `lib/` stays clean. The last code commit before merge deletes
`spike/` and restores `pubspec.*`, `android/` and `.github/` to `main`'s state,
except changes a decision keeps (`minSdk`, D-070). The merge commit keeps that history
reachable; each spike page cites the SHA of the last commit holding its code. Check
before merge: `git diff --stat origin/main...HEAD` shows only `docs/` and the kept
changes. This round merges as "M0.4, part 1", stated as partial.

## Key interfaces (spike code; "carried" designs go forward)

- `readTanzilXml(Uint8List)` → `List<TanzilAyah>`: strict UTF-8; refuses entities,
  CDATA, processing instructions other than the declaration, unknown elements and
  attributes; text is an exact substring whose UTF-8 bytes equal the source bytes at
  its offset; the copyright comment returned verbatim. Never trims, normalises or
  re-encodes; a failure stops and reports.
- `writeSpikePack(root, …)`: `<root>/spike-tanzil-uthmani/1/` to `docs/CONTENT_PACKS.md`;
  words are the tokens between U+0020 (spike only; B0.4 and D-038 decide); divisions
  synthetic and flagged so; the Tanzil notice kept verbatim. The app's verification
  and the integrity suite are the safety net for this writer.
- `cmapCodePoints(Uint8List ttf)`: formats 4 and 12.
- `SurahTextBlock` (carried to M1.2): `ayat: List<PackText>`, `basmala`, `words`,
  `markers` (`AyahMarker` children), `highlighted`, `centreLastLine`, `onWordTap`;
  the render object exposes `hit(Offset)`, `boxesOf(QuranAddress)`, `topOf(ayah)`,
  `lineStarts`. Whole values side by side; slicing only at stored offsets.
- `FrameStats.from(List<FrameTiming>)`; `processAge()` from `/proc`.
- S3: `toneWav(...)` (a beep every 10 s); `SpikeAudioHandler` over `AudioPlayer`
  (carried to M1.9 as the engine-service shape); `analyse(samples)` → continuity
  report.
- S5: `SpikeDownloader`; `PackStore(root)` (carried to M1.4): `staging/<id>/<version>/`,
  `packs/<id>/<version>/`, `packs/<id>/current`; `activate` by rename, never
  overwriting a version, keeping one previous; `rollback`; `recover()` at start-up.
  `PackDownloadQueue`: manifest, files, `verify`, one retry of a failed file, then
  activate or keep the current version.

## Tests and where each thing is measured

Linux (`flutter test`, every push; timings are debug figures, never compared with NF
budgets):

- S1, synthetic: each word's box centre hits that word; boxes non-empty and one per
  line; `topOf` monotonic; V1 and V2 give the same line starts; no overflow at 320,
  360 and 412 wide at 2.0x; last-line centring moves only the last line; an ayah
  sliced at its stored offsets has the same width and boxes as unsliced; the XML
  reader refuses bad input and keeps bytes; the writer's pack passes the integrity
  suite.
- S3: WAV header, length and beeps; the continuity analyser on made-up logs.
- S5 against the loopback server: clean run; drop and resume with `Range` (bytes
  served at most size plus one chunk); corrupt once, re-fetched; corrupt twice, not
  activated; update then rollback; no overlap; recovery from leftovers.

Linux on the real text (CI task `spike-s1-text`): `cmap` coverage of every code point
(no fallback font); hit-test round trip and slicing equality over every word and
ayah; mark-only token count (input to D-038, P3); justification stretch; ink at line
band edges at 1.0x and 2.0x; layout time per surah; line-start fingerprint per surah;
the integrity suite on the whole text. Output is numbers, `U+XXXX` code points and
addresses only.

Device (the profile APK, the owner's Android phone): NF-02 frame timings scrolling the
longest surah, V1 and V2; NF-01 ten cold starts; 200% with the system setting; tap
hit test; line-start fingerprints against Linux; S3 70-minute locked playback and
controls; S5 Wi-Fi gating, resume after drop and after force-stop, corrupt file, low
space, update and rollback.

Stays pending until measured on a device: NF-01, NF-02, 200%, the fingerprint match,
all of S3, the native downloader's behaviour; every iOS figure (D-042); a second OS
version (one phone only); real-network resume (O-08, M1.4).
