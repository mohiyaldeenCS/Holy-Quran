## Key interfaces

- `Result<T>`: sealed, `Ok<T>(value)` and `Failure<T>(Exception error)`.
- `QuranAddress(riwaya, surah, ayah, [word])`: canonical `hafs:2:255` and
  `hafs:2:255:3`; ASCII digits only, no sign, no leading zero, positive; no upper
  bound in code (counts come from the pack); comparing across riwayat throws; an ayah
  sorts before its words. `parse`, `tryParse`, `toString` round-trips.
- `QuranRange(start, end)`: same riwaya and granularity, `start <= end`; forms
  `hafs:2:255-2:260` and `hafs:2:255:3-2:255:7`; `contains`.
- `PackText.fromPack(String)`: opaque; `verbatim` is the only accessor; `toString`
  never shows the value.
- `SurahInfo`, `WordSpan` (UTF-16, half-open), `EditionMap` (`count`, `numberAt`,
  `startOf`, `isSajda`; divisions juz, hizb, rub, page), `VerifiedPack`,
  `PackManifest` and its parts, sealed `PackFailure` (`ManifestUnreadable`,
  `SignatureRejected`, `UnsupportedPackFormat`, `FileHashMismatch`,
  `SurahHashMismatch`, `TextEncodingRejected`, `AddressNotInPack`, `PackDisabled`).
- `ManifestSignatureVerifier` with `SignatureNotConfigured`, which reports
  `notChecked` and never `valid`.
- `PackFileService` (`readIfExists`, `sizeOf`, `sha256Of` streamed in an isolate).
- `PackDatabase.open(path, formatVersion:)`: the only file importing `sqlite3`;
  read-only and immutable; checks `application_id` and `user_version`; reads text as
  BLOB and decodes strict UTF-8, rejecting a leading U+FEFF; computes the surah
  digest; the only producer of `PackText` (the debug gallery aside).
- `PackRepository.verify(directory)` → `Result<VerifiedPack>`: signature, strict
  parse, size and SHA-256 of every file. `invalid` signature rejects; `notChecked`
  passes flagged while D-024 is open.
- `QuranTextRepository`: `riwaya`, `font`, `surahs`, `ayahText`, `basmala`, `words`,
  `editionMap`, `contains`. The first read of a surah in a session checks its digest;
  a mismatch disables the pack for the session.

## Tests

- Unit: address and range (round trip, every malformed form, order, ranges); manifest
  parsing (every field, hash format, bare file names, kinds, versions); file service;
  database (read-only refusal, file hash unchanged after reads, no sidecar files);
  repositories (verify, signature cases, surah digest mismatch then disabled);
  edition map boundaries.
- Integrity suite (`definePackIntegritySuite`), on synthetic packs in CI, on
  `assets/packs/*` when they exist, and on `--dart-define=HOLYQURAN_PACK_DIR=<dir>`
  for stream B: verification; contiguous numbering; counts against the manifest;
  production and independent digests; stored bytes equal `verbatim` for every ayah;
  no leading BOM; word spans in bounds, ordered, rejoining; division and sajda
  references; header bytes, `application_id`, `user_version`; the manifest's font
  equals the pinned Amiri Quran file.
- Display: for every ayah of a synthetic pack, `QuranText` built from the real data
  layer carries exactly the stored bytes.
- Rejection: each faulty synthetic pack (flipped byte, wrong surah hash, wrong
  counts, leading U+FEFF, WAL header, wrong `application_id` or `user_version`,
  unsupported version, a path in a file name) is refused through the production path.
- Synthetic packs include NFC-unstable text, leading, trailing and double spaces, and
  a non-BMP character, so any normalising, trimming or offset error changes bytes.
- Guards:
  - `pack_text_guard_test`: `verbatim` only in `pack_text.dart` and the sink list
    (today `quran_text.dart`); `PackText.fromPack` only in `pack_database.dart` and
    the debug gallery; no normalisation identifier or package in `lib/`; self-tests.
  - `pack_write_guard_test`: `sqlite3` imported only by `pack_database.dart`; every
    open is read-only, URI, immutable; no `execute`, in-memory copy or backup; no SQL
    write verb or `PRAGMA x =` in `lib/data/`; no `dart:io` write API in
    `lib/data/services/pack_*.dart`; self-tests.
  - `import_rules_test`: `lib/domain` also imports no `dart:io`, `dart:isolate`,
    `dart:ffi`.

## Package notes (checked on pub.dev, 2026-10-07)

`sqlite3` 3.7.0 is the latest, but Flutter 3.44.7 pins `hooks` at 2.0.2, so it
resolves to 3.5.2 (bundled SQLite 3.53.4, FTS5). Its binaries target Android API 24
and iOS 12, below the app's minimums. Tests download the SQLite binary through the
build hook. `sqlite3_flutter_libs` is end of life. `sqflite` uses the system SQLite
through platform channels, which varies by Android version.
